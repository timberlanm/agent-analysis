# 账号、角色与权限（RBAC）手册

本工作台在 [运行手册（RUN.md）](./RUN.md) 的基础上，提供**登录认证 + 角色权限 + 审计**。
本文覆盖：首次初始化、角色与权限、服务令牌、审计、配置项、测试。

---

## 1. 首次启动与初始管理员

首次启动（`start.bat` 或 `python backend/app.py --serve-frontend`）时，系统检测到无任何账号，会**自动创建管理员 `admin` 并在控制台醒目打印一次性初始口令**：

```
!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!
  首次启动：已创建初始管理员账号
    用户名：admin
    一次性初始口令：xxxxxxxxxxxx
  请立即登录并修改口令（登录后会强制要求修改）。此口令仅显示这一次。
!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!
```

- 该口令**只显示这一次**，请立即保存；登录后会**强制修改**。
- 忘记口令时，可停止服务、删除库中 `users` 表记录（或整库）后重启，重新生成 admin。
- 会话签名密钥自动生成并落盘 `backend/data/secret_key`（已 gitignore，**切勿入库**）。

登录后，用右上角头像菜单进入 **账号管理 / 审计中心**。

## 2. 角色

内置 6 个角色（`admin` 为超级用户，拥有全部权限）：

| 角色 | code | 职责 |
|---|---|---|
| 系统管理员 | `admin` | 账号 / 角色 / 系统治理，拥有全部权限 |
| 研判主管 | `triage_lead` | 分派、驳回、重研、监督，研判全流程；不受“本人经手”限制 |
| 研判员 | `analyst` | 录入、研判、定性、流转、记录（默认仅限本人经手的告警） |
| 应急处置人 | `responder` | 承接并更新处置子任务，仅可见/操作受指派的告警 |
| 审计员 | `auditor` | 只读 + 审计日志 + 导出 |
| 只读访客 | `viewer` | 只读告警 |

一个账号可兼多个角色（如“研判员 + 应急处置人”），权限取并集。

## 3. 权限与对象级收敛

- **权限门控**：每个写操作/敏感读接口都要求对应权限，默认拒绝。
- **对象级收敛（越权防护）**：`analyst`/`responder` 等非豁免角色，只能操作**与自己有归属关系**的告警——
  - “本人经手” = 该告警的 owner / 处理人 / 创建者；
  - “受指派” = 处理人 或 其处置子任务的负责人。
  - `admin`/`triage_lead` 不受对象级限制。
- **可配置**：管理员可在「账号管理 → 角色权限」中，用勾选矩阵调整每个角色拥有哪些权限（`admin` 角色不可改，始终全权）。**保存后相关用户重新登录即生效**。
  - 注：对象级“本人经手/受指派”的归属策略为内置规则，不在该矩阵内调整。

## 4. 服务令牌（自动化入库）

供 SIEM / EDR 等**外部系统**通过 HTTP 自动推送告警，无需人工会话。

- 在「账号管理 → 接口令牌」创建，**明文令牌仅创建时显示一次**（库中只存 SHA-256 哈希）。
- 令牌权限被**白名单**限制为低危入库类：`alert.create` / `alert.view` / `attachment.write` / `alert.note`（无法被授予删除、清空、管理等能力）。
- 调用方式（二选一）：

```
POST /api/incident/alerts
Authorization: Bearer svc_xxxxxxxx
# 或
X-API-Token: svc_xxxxxxxx
```

- 令牌走请求头、不依赖 cookie，天然免疫 CSRF；可随时吊销。
- 说明：仓库内 `tools/seed_edr_alerts.py` 走服务层直连写库、不经 HTTP，**不需要令牌**。

## 5. 审计

- 所有关键操作、登录 / 登出 / 登录失败、**鉴权拒绝（权限不足）**、角色权限变更、账号与令牌变更均入审计。
- 每条审计记录 `actor_user_id`（硬关联真实账号，改名也能追溯）与操作人用户名快照。
- **防篡改哈希链**：每条审计带前后哈希；任何行被改都会破链。「审计中心」顶部显示完整性校验结果，`GET /api/incident/audit/verify` 可编程校验。
- 「审计中心」（`audit.view` 权限：审计员 / 主管 / 管理员）支持按 操作人 / 动作 / 关键词 / 时间范围 检索与 CSV 导出。

## 6. 配置项（环境变量）

| 变量 | 默认 | 说明 |
|---|---|---|
| `ALLOWED_ORIGINS` | `http://localhost:3000,http://127.0.0.1:3000` | 开发直连的跨域来源；生产单端口同源无需 CORS |
| `SECURE_COOKIE` | `False` | 反代启用 HTTPS 时置 `True`，会话 cookie 带 Secure |
| `COOKIE_SAMESITE` | `Lax` | 同源部署用 Lax 即可抵御 CSRF |
| `INCIDENT_DB_PATH` | 仓库内 `backend/data/analysis_store.db` | 覆盖 SQLite 库路径（测试隔离用） |

会话策略（`backend/services/auth_service.py`）：空闲超时 60 分钟、绝对超时 12 小时，服务端可撤销（改角色/停用/改密即失效）。口令：哈希存储、最小 8 位、首次/重置强制改密。**未启用**“登录失败自动锁定”（失败尝试仍记入审计）。

> 生产建议：置于 HTTPS 反向代理之后并设 `SECURE_COOKIE=True`；管理员账号尽量少并与审计员分离。

## 7. 运行测试（RBAC 回归）

```bash
pip install -r backend/requirements-dev.txt   # 安装 pytest（可加国内镜像）
python -m pytest backend/tests/ -q
```

测试使用临时库（`INCIDENT_DB_PATH`），**不会触碰仓库内的数据库**。覆盖：登录门控、对象级越权、读范围收敛、服务令牌、审计防篡改、无失败锁定、可配置权限。
