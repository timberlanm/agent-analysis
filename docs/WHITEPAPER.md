# 研判分析工作台 · 功能白皮书

> 面向安全运营（SOC）与应急响应团队的告警研判处理平台
> 文档版本：v1.0 ｜ 适用产品：Incident Analysis（研判分析工作台）

---

## 1. 产品概述

**研判分析工作台**是一套面向一线安全运营与应急响应工程师的告警**研判处理闭环**平台。它把来自各类安全设备的告警统一接入、归一化，围绕「**状态 · 结论 · 处理人**」三要素驱动一条从**录入 → 研判 → 处置 → 完成**的完整闭环，并对全过程留痕审计。

平台的定位不是又一个告警堆积的看板，而是解决三个真实痛点：

1. **告警来源杂、字段乱** —— 不同设备（EDR/HIDS/NDR/WAF/SIEM…）字段名各异，研判员反复人工摘录 IOC。
2. **研判过程不闭环** —— 结论、状态、处理人各管各的，改了结论忘了改状态，处置动作无处落地。
3. **过程不可追溯** —— 谁在什么时间基于什么证据下了什么结论、做了什么处置，事后说不清。

平台运行期**本地离线、单端口部署**，数据存于本地 SQLite，不依赖云服务与大模型。

---

## 2. 设计理念

| 理念 | 含义 |
|------|------|
| **研判闭环优先** | 以状态机约束流程，结论驱动路由，完成设门控——不让告警"烂尾"或"跳步"。 |
| **人机协同** | 机器负责"省录入"（归一化、OCR、正则抽取 IOC），人负责"保准确"（核对、下结论、决定处置）。 |
| **过程留痕** | 每一次状态变更、结论改判、处置动作、证据上传都记入研判记录与审计日志。 |
| **本地自持** | 运行期离线可用，数据、附件、模型均在本地，适配隔离网/内网环境。 |

## 3. 核心功能

### 3.1 多源告警接入与字段归一化

- 支持 **EDR、HIDS、NDR、WAF、SIEM、其他** 六类安全设备模板录入，也支持 API 上报原始 JSON。
- **字段别名归一化**：同一语义字段在不同设备里名称各异（源 IP 可能是 `src_ip`/`sip`/`attacker_ip`…），平台自动映射到统一字段集，输出规整的「告警详情」。
- **实体自动抽取**：对告警文本用正则提取 IP / 域名 / 文件 Hash / URL / 文件路径等 IOC，作为关联分析的基础。
- 原始报文完整留存，归一化视图与原文并存、互不覆盖。

### 3.2 研判工作台（状态 · 结论 · 处理人联动）

- 一屏承载：上报信息、告警截图/证据、告警详情、研判状态、**研判信息**、处置子任务、研判记录、流转/审计记录。
- **研判信息**收敛为两项必填：**研判依据（含举证）**、**处置建议**；三个独立确认合并为单一「提交研判信息」，非空即入研判记录、缺失则提示。
- 结论、状态、处理人三者按规则联动，避免人工维护不一致（详见第 4 节）。

### 3.3 研判处理闭环（本平台核心）

以状态机 + 结论驱动路由 + 完成门控 + 闭环回流构成完整闭环，详见 **第 4 节**。

### 3.4 智能字段识别（截图 OCR + 文本解析）

针对"上报人只给了截图 / 只粘贴了一段文字、没有结构化报文"的常见场景：

- **截图识别**：详情页「从截图识别字段」，本地 OCR（RapidOCR，离线、中英文、CPU）把告警截图转文字，再抽取字段预填「告警详情」。
- **文本识别**：上报页「告警详情」框粘贴文本即自动识别，或点「从文本识别字段」，无需 OCR 引擎（纯规则）。
- **两段解析**：① 逐行「标签: 值」（支持中英文冒号 / 等号 / 空格分隔，能区分源/目的 IP）；② 正则兜底抽取 IP/Hash/域名/路径，并剔除 `powershell.exe` 之类文件名误判为域名。
- **人工核对为准**：所有识别结果标"待确认"，研判员在核对对话框里逐项勾选/修改；可从 OCR 原文选中文本、**自定义任意字段名**补充后一并写入。
- **优雅降级**：未安装 OCR 引擎时，识别功能给出安装指引，其余功能不受影响。

### 3.5 应急处置子任务

- 结论为「安全事件」自动转入**应急响应中**，或研判员按需在任意结论下挂处置动作。
- 子任务轻量三态：**待处理 / 处理中 / 已完成**，可指派处理人（如"封禁 IP，需外部团队执行"）。
- 覆盖"真实攻击但未遂/未成规模，仍需封禁处置"等现实场景——每个结论都有对应处置路径，没有"无需处置"的黑洞。

### 3.6 证据与附件管理

- 支持**图片、日志、PCAP/PCAPNG、压缩包**等附件，可点击 / 拖拽 / Ctrl+V 粘贴上传。
- 设备告警截图归入「告警截图/证据」；研判过程中粘贴的举证截图归入「研判记录」，两者分区不混。
- 图片按实际尺寸自适应展示。

### 3.7 关联分析

- 基于 IP / Hash / 域名 / URL 等实体，自动发现共享同一 IOC 的关联告警，辅助判断是否同一攻击活动。

### 3.8 审计与留痕

- **研判记录**：时间线呈现每一步研判动作、结论改判、证据（文字+图片内联）。
- **审计日志**：完整记录告警的创建、编辑、状态/结论变更、指派、处置、导出等操作历史。

### 3.9 数据导出

- 单条告警导出 **JSON / Markdown**（便于归档、写报告、交接）。
- 运营统计导出 **CSV**。

## 4. 研判处理闭环详解

### 4.1 告警状态（主生命周期）

```
新建中(new) → 待分配(pending) → 研判中(investigating) → 应急响应中(responding) → 已完成(closed)
```

### 4.2 研判结论

| 结论 | 含义 |
|------|------|
| 告警误报（false_positive） | 非真实威胁 |
| 正常业务（business） | 正常业务行为触发 |
| 真实攻击（true_positive） | 确为攻击，未必成规模/可能未遂 |
| 安全事件（incident） | 需要应急响应的安全事件 |
| 无法确认（unknown） | 证据不足，暂无法定性 |

### 4.3 结论驱动路由（关键规则）

- **仅「安全事件」自动转入「应急响应中」**。「真实攻击」不自动跳转——它未必成规模（如未遂），留在研判中，需要时人工转应急或直接挂处置子任务（如封禁 IP）。
- **状态→结论一致性（软处理）**：进入「应急响应中」时，若当前结论为非事件类（误报/正常业务/无法确认），自动**作废为"未定"**并记录一条说明——只清不伪造，留待重研。
- **结论翻转软清空**：结论由 A 改为 B 且已有研判内容时，旧内容整段归档进研判记录，处置建议清空、研判依据标记"待复核"，避免旧结论的痕迹污染新判断。

### 4.4 完成门控

- 置为「已完成」前校验**研判依据**与**处置建议**两项非空，缺失则拒绝完成——保证每条闭环的告警都有据可查、有处置可循。

### 4.5 闭环回流（已完成可重开）

| 入口 | 行为 |
|------|------|
| **重新指派** | 清空结论与研判快照，带入新处理人 → 研判中 |
| **驳回重判** | 清空结论、处理人与研判快照 → 待分配 |
| **重新研判** | 直接改判结论、保留处理人、轮次 +1；事件类结论 → 应急响应中，否则 → 研判中 |

每次回流轮次 +1，流转记录完整保留，可追溯每一轮研判。

## 5. 技术架构

```
┌──────────────────────────────────────────────┐
│  浏览器（单页应用）                            │
│  Vue 3 + Element Plus                          │
└───────────────┬──────────────────────────────┘
                │  HTTP / JSON（/api）
┌───────────────▼──────────────────────────────┐
│  Flask 后端（单端口托管 API + 前端静态产物）   │
│  ├─ 告警/研判/子任务/关联/审计/导出 接口        │
│  ├─ 归一化 + 实体抽取（正则 IOC）              │
│  └─ OCR 服务（可选，本地 RapidOCR）            │
└───────────────┬──────────────────────────────┘
                │
┌───────────────▼──────────────────────────────┐
│  本地存储：SQLite（数据） + 文件系统（附件）   │
└──────────────────────────────────────────────┘
```

| 层 | 技术 |
|----|------|
| 前端 | Vue 3.3 / Element Plus 2.3 / Vite 4 |
| 后端 | Python 3.8+ / Flask 2.3 |
| 数据 | SQLite（业务数据）+ 本地文件（截图/日志/附件） |
| OCR（可选） | RapidOCR（ONNX，离线、中英文、CPU） |
| 部署 | Flask 单端口托管 API + 前端，`start.bat` 一键启动 |

**特点**：零外部服务依赖、运行期离线可用、不依赖大模型/GPU，适配内网与隔离环境。

## 6. 部署与运行

- **一键启动**：Windows 下 `start.bat` 自动检查依赖、按需构建前端、启动服务并打开浏览器；脚本自动判断前端是否需要重建，无需手动选择。
- **访问**：默认 `http://localhost:5000`；后端监听 `0.0.0.0`，同网段主机可通过 `http://<主机IP>:5000` 访问。
- **前置条件**：Python 3.8+、Node.js 16+（首次构建用）、首次安装依赖需联网。
- 详见 [安装准备（INSTALL.md）](INSTALL.md) 与 [运行手册（RUN.md）](RUN.md)。

## 7. 典型使用场景

- **日常告警研判**：多源告警统一接入，按严重度/来源/状态/结论筛选，逐条研判下结论。
- **只有截图/文本的上报**：OCR/文本识别自动提取 IOC 预填，省去人工摘录。
- **可疑外联 C2 改判**：初判误报，补充上下文后改判真实攻击/安全事件——结论翻转自动归档旧研判、软清空、必要时转应急。
- **应急处置协同**：安全事件转应急，拆解封禁 IP、清除木马等处置子任务并指派跟踪。
- **复盘与交接**：一键导出单条告警的 JSON/Markdown，附完整研判记录与审计轨迹。

## 8. 附录：核心枚举

**告警状态（主）**：新建中 / 待分配 / 研判中 / 应急响应中 / 已完成
**研判结论**：告警误报 / 正常业务 / 真实攻击 / 安全事件 / 无法确认
**严重程度**：critical / high / medium / low / info
**处置子任务状态**：待处理 / 处理中 / 已完成
**设备模板**：EDR / HIDS / NDR / WAF / SIEM / 其他
**归一化字段**：源IP、目的IP、源端口、目的端口、主机名、用户名、域名、URL、文件 Hash、文件路径、进程名、命令行、规则名称、规则 ID、协议、HTTP 方法、响应状态、User-Agent、检测动作（研判员可增补任意自定义字段）
